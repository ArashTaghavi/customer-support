# AI Knowledge, Support & Workflow Platform

> یک پلتفرم چندسازمانی برای مدیریت دانش شرکت، پشتیبانی هوشمند مشتریان و اجرای فرایندهای عملیاتی با تأیید انسانی.

## معرفی پروژه

این محصول ترکیبی از سه حوزه **Advanced RAG**، **AI Customer Support Agent** و **Workflow Automation** است. هر سازمان منابع دانش، قوانین، کاتالوگ محصولات و اتصال‌های عملیاتی خود را تعریف می‌کند؛ مشتریان با دستیار گفتگو می‌کنند و دستیار با استناد به منابع معتبر، اطلاعات ارائه می‌دهد یا عملیات مجاز را از طریق ابزارها انجام می‌دهد.

**اصل طراحی:** پاسخ مبتنی بر دانش با عملیات واقعی متفاوت است. RAG برای یافتن اطلاعات و سیاست‌هاست؛ ابزارهای متصل برای خواندن/تغییر داده‌های زنده؛ Workflow برای هماهنگی مراحل، تأیید و بازیابی اجرا.

## اهداف

- ایجاد یک محصول مستقل و قابل ارائه به‌عنوان SaaS، نه یک نمونه آموزشی.
- پشتیبانی چندسازمانی با جداسازی کامل داده‌ها و مجوزها.
- پاسخ دقیق، قابل استناد و قابل ارزیابی از روی اسناد و قوانین شرکت.
- اجرای امن عملیات فروشگاه، سفارش و پشتیبانی با Agent و ابزارها.
- پشتیبانی از Workflowهای چندمرحله‌ای، تأیید انسانی، توقف و ادامه اجرای پایدار.
- قابلیت مشاهده، ارزیابی، تست، استقرار و توسعه‌پذیری در سطح Production.

## استک پیشنهادی

| لایه | انتخاب اصلی |
| --- | --- |
| وب و پنل | Laravel + Inertia React + TypeScript + Tailwind CSS |
| API و سرویس AI | FastAPI + Pydantic + SQLAlchemy + Alembic |
| Agent و Orchestration | LangGraph + LangChain |
| RAG | LangChain، PostgreSQL + pgvector، Hybrid Retrieval و Reranker |
| داده‌های عملیاتی | PostgreSQL |
| Queue و Cache | Redis + Celery برای کارهای AI؛ Laravel Queue برای کارهای وب |
| اتصال ابزارها | ابزارهای داخلی با قرارداد مشخص؛ MCP برای اتصال‌های سازگار |
| Observability | Langfuse + OpenTelemetry |
| Evaluation و Testing | pytest، تست یکپارچه، مجموعه داده ارزیابی و DeepEval/RAGAS در صورت تناسب |
| استقرار | Docker Compose در توسعه؛ CI/CD و استقرار متناسب با مقیاس |

> تکنولوژی‌ها انتخاب اولیه‌اند؛ استفاده از هر کدام باید با نیاز واقعی توجیه شود. LangGraph مسئول اجرای Stateful Agent است و Celery جایگزین Checkpointing آن نیست.

## نیازمندی‌های کلیدی معماری

- احراز هویت، RBAC، Tenant Isolation، کنترل مالکیت منابع و Audit Log.
- ابزارهای خواندنی و نوشتنی جدا، اعتبارسنجی ورودی و خروجی و کنترل مجوز در سرور، نه صرفاً در Prompt.
- عملیات مالی/سفارش با تأیید معتبر، Idempotency Key، تراکنش دیتابیس و مدیریت شکست جزئی.
- Checkpointer پایدار برای LangGraph، شناسه مستقل برای هر Workflow Run، ثبت وضعیت و Resume امن.
- تفکیک محیط آزمایشی از محیط واقعی، جلوگیری از Prompt Injection و محدودسازی دسترسی ابزارها.
- مدیریت نسخه اسناد، منبع/صفحه Citation، حذف و Reindex، ارزیابی کیفیت بازیابی و پاسخ.
- Streaming، Retry، Timeout، Rate Limit، ثبت هزینه/توکن و مدیریت خطا.
- حفاظت از اطلاعات مشتری، حذف داده، حداقل‌سازی PII و مدیریت Secretها.

## سناریوهای پذیرش نهایی

1. **پرسش دانشی:** مشتری درباره گارانتی می‌پرسد؛ پاسخ با استناد به بند دقیق سند شرکت ارائه می‌شود.
2. **مقایسه محصول:** مشتری دو گوشی را مقایسه می‌کند؛ ویژگی‌ها، قیمت و موجودی از داده معتبر دریافت می‌شوند.
3. **ثبت سفارش:** مشتری محصول انتخاب می‌کند؛ Agent سبد و مبلغ را تأیید می‌گیرد و سفارش را بدون ثبت تکراری ایجاد می‌کند.
4. **لغو سفارش:** Agent شرایط را بررسی می‌کند، منتظر تأیید می‌ماند و پس از Resume سفارش را با کنترل مجوز لغو می‌کند.
5. **چند تأیید هم‌زمان:** دو درخواست لغو مستقل، دو اجرای جدا دارند و پاسخ هر تأیید فقط همان اجرا را ادامه می‌دهد.
6. **مرجوعی:** Agent قوانین را از Knowledge Base می‌خواند، وضعیت سفارش را از ابزار می‌گیرد و درخواست را ثبت یا ارجاع می‌دهد.
7. **ارجاع انسانی:** در صورت ابهام، تیکت با خلاصه گفتگو و منابع برای اپراتور ساخته می‌شود.
8. **جداسازی سازمانی:** هیچ کاربر یا Agent نتواند سند، سفارش یا اجرای سازمان دیگر را بخواند یا تغییر دهد.

## تعریف پایان پروژه

پروژه زمانی آماده ارائه است که سناریوهای اصلی با UI کامل کار کنند، عملیات حساس امن و قابل بازیابی باشند، RAG ارجاع معتبر بدهد، تست‌های کلیدی سبز باشند، و Trace و Audit هر اجرای Agent/Workflow قابل مشاهده باشد.
